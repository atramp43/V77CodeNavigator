# V77CodeNavigator

Первая диагностическая версия для штатного редактора Конфигуратора 1С 7.7.
Реализованы этапы 1–2: исследование и безопасный сбор сведений. F12, возврат и список
процедур в реальном редакторе пока не подключены. Решение об адаптере принимается
после анализа отчёта с 7.70.932.

## Запуск

Откройте `builds/diagnostic-win-x64/V77CodeNavigator.exe`. Нужен **.NET 8 Desktop
Runtime x64**, не только обычный .NET Runtime. EXE необходимо оставлять вместе
с DLL, `.deps.json` и `.runtimeconfig.json` внутри дерева проекта.

1. Откройте текст модуля в Конфигураторе.
2. Нажмите «Собрать отчёт через 7 секунд».
3. Переключитесь в 1С и установите курсор в тексте до окончания отсчёта.
4. До завершения снимка оставляйте Конфигуратор активным (до 30 секунд).
5. Передайте файл `logs/diagnostic-*.json`. TXT рядом — краткая сводка.

По умолчанию код, заголовки окон и UIA Name/Value не сохраняются. Для первого
отчёта оставьте флажок включения содержимого снятым.

## Сборка и проверка

```powershell
powershell -ExecutionPolicy Bypass -File .\build.ps1
```

Скрипт не меняет системную execution policy. Требуется .NET SDK с установленными
targeting packs .NET 8 и Windows Desktop 8, а также host pack win-x64. Внешних
NuGet-зависимостей нет; NuGet.Config отключает источники пакетов для воспроизводимой
офлайн-сборки. Решение Visual Studio: `V77CodeNavigator.sln`.

Документация: [исследование](docs/RESEARCH.md), [архитектура](docs/ARCHITECTURE.md),
[тестирование](docs/TESTING.md), [инструкция](docs/USER_GUIDE.md).

Исходники, obj/bin, сборки, кэш сборки и журналы размещаются в каталоге проекта.
Приложение не изменяет 1cv7.exe, модули или базы, не использует собственное внедрение
DLL, буфер обмена, SendInput, клавиатурные hooks или регистрацию горячих клавиш.
