# Архитектура диагностической версии

- `V77CodeNavigator`: WinForms UI, семисекундный отсчёт, отдельный рабочий процесс,
  тайм-аут 30 секунд, сохранение краткой сводки.
- `V77Navigator.Core`: политика выбора процесса/класса, автономный лексический
  индекс объявлений и ограниченная история позиций. К 1С они пока не подключены.
- `V77Navigator.WinApi`: объявления WinAPI, перечисление и классы окон, сведения
  GUI-потока, чтение сообщений с тайм-аутом 300 мс.
- `V77Navigator.Diagnostics`: JSON-модель, сбор HWND/PID/TID, стандартные read probes,
  UIA и MSAA. Сохранение промежуточных снимков через временный файл и rename.

UI не забирает фокус при сборе. Рабочий процесс сначала проверяет имя процесса
1cv7 и маркер Конфигуратор/Configurator в заголовке корня foreground. Это
консервативная эвристика, а не идентификация модуля: нестандартный заголовок приведёт
к отказу. При нескольких экземплярах исследуется только активный.

EnumChildWindows ограничен 512 HWND. Для фокуса, MDI child и root проверяются
UIA-поддеревья: максимум 64 элемента на цель, глубина 4, ограниченная очередь.
Дополнительно проверяется ProcessId UIA. Данные получаются последовательно:
закрытие окон или смена фокуса во время снимка могут дать частичный результат.
Фокус/MDI child всегда обозначены кандидатами, редактор автоматически не подтверждается.

Запись/движение отсутствуют. WM_GETTEXT и EM_GETSEL отправляются только exact
известным классам под фокусом. Прочие классы исследуются через read-only accessibility.
WM_GETTEXT ограничен миллионом символов. UIA DocumentRange.GetText — 1 000 001 символом.
UIA TextPattern2 проверяется по списку patterns (10024); GetCaretRange не вызывается.
Для выделения через TextPattern сохраняются число диапазонов и признак свёрнутости;
символьные смещения и логические номера строк пока не вычисляются.
EM_LINEFROMCHAR даёт display line; переносы по ширине могут отличаться от строк исходника.
Позиция активного конца непустого выделения неизвестна. GUITHREADINFO caret rectangle
не является номером строки или символьным смещением.

UIA/MSAA могут зависнуть внутри чужого provider: worker отделён от UI. После 30 секунд
контроллер завершает только собственный worker, сохраняя последний checkpoint.
Если один provider завис, последующие цели не исследованы. Закрытие UI на время сбора
блокируется, чтобы не оставить worker без контроля. Полноценная отмена — будущая доработка.

Без включения содержимого исключены caption, UIA Name, Value, DocumentText и MSAA
Name/Value. Текст стандартного контрола/UIA может кратковременно читаться в память
для проверки длины, но не записывается в JSON. Исключения сохраняются как тип/HRESULT,
без Message. Отчёт всё равно содержит классы окон, числовые идентификаторы, время и версию ОС.

Следующий этап: интерфейсы получения текста/позиции и навигации только после реальной
диагностики. Обработка F12 потребует проверки foreground на каждом событии, идентичности
документа при восстановлении и отсутствия побочных действий при неоднозначности.
Парсер возвращает все одноимённые определения; случайный выбор первого не предусмотрен.
